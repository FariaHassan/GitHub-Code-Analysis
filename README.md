# 1. ConnectorJmxExporter.java
# Description
The ConnectorJmxExporter class is responsible for exposing FIX session connectors to the Java Management Extensions (JMX) framework so that they can be monitored and managed during runtime. It acts as the entry point for registering connector-related MBeans and ensures that every connector receives a unique JMX object name.
The class maintains a static AtomicInteger that automatically generates unique connector IDs whenever a connector is registered without a custom identifier. This guarantees that multiple connectors can coexist without naming conflicts. The main functionality is implemented through two overloaded register() methods. One method automatically assigns a connector ID, while the other allows the caller to specify the connector ID manually.
During the registration process, the class first generates an ObjectName using the private getConnectorName() method. This method builds the JMX object name by combining properties such as the connector type, whether the connector acts as an Acceptor or Initiator, and its unique identifier. After creating the object name, the class determines the runtime type of the connector using the instanceof operator. If the connector is an AbstractSocketAcceptor, it creates a SocketAcceptorAdmin object. If it is an AbstractSocketInitiator, it creates a SocketInitiatorAdmin object. If the connector belongs to an unsupported type, the class throws a QFJException indicating that the connector cannot be managed.
Once the appropriate management object has been created, it is registered with the supplied JmxExporter, making it available through the JMX management system. The class also performs proper exception handling by allowing runtime exceptions to propagate while wrapping checked exceptions inside a QFJException with an informative message. Finally, the lookupSessionName() method delegates session lookup requests to the SessionJmxExporter, allowing other components to retrieve the JMX object name associated with a specific FIX session.
Overall, this class serves as the bridge between FIX connectors and the JMX management infrastructure by creating connector-specific management objects, registering them, assigning unique identities, and providing access to exported session information.
# 2. SocketAcceptorAdmin.java
# Description
The SocketAcceptorAdmin class provides the JMX management implementation for socket acceptors within the QuickFIX/J engine. It extends the abstract ConnectorAdmin class and implements the SocketAcceptorAdminMBean interface, inheriting common connector management features while adding functionality specific to acceptor connections.
The constructor receives references to the JMX exporter, the socket acceptor, the connector's JMX object name, and the session exporter. These objects are passed to the parent class to initialize common management functionality, while the acceptor reference is stored locally for performing acceptor-specific operations.
One of the main responsibilities of this class is to expose network information about active acceptor sessions. The getAcceptorAddresses() method retrieves all session-to-address mappings from the underlying socket acceptor. It iterates through every active session, extracts the corresponding SessionID and network address, and creates instances of the inner SessionAcceptorAddressRow class. Each row stores the session identifier, the socket address, and the JMX object name associated with the session. These rows are then converted into JMX TabularData using the TabularDataAdapter, making the information accessible through standard JMX monitoring tools.
The inner SessionAcceptorAddressRow class acts as a simple data container. It provides getter methods that expose the session identifier, session name, and a formatted IP address with its port number. This formatting makes the information easier to display in monitoring applications.
The class also provides the getQueueSize() method, which returns the current size of the connector's internal message queue. This value helps administrators monitor connector workload and identify potential message processing bottlenecks.
Exception handling is performed by converting JMX-related exceptions into IOException objects using the JmxSupport utility class. This ensures consistent error reporting while keeping the management interface simple for external clients.
Overall, this class specializes in monitoring incoming FIX connections by exposing session addresses, queue statistics, and structured management data through JMX.
# 3. SocketInitiatorAdmin.java
# Description
The SocketInitiatorAdmin class provides JMX management functionality for socket initiators in the QuickFIX/J framework. Similar to SocketAcceptorAdmin, it extends the common ConnectorAdmin class but focuses on monitoring outgoing FIX connections instead of incoming ones.
The constructor initializes the object by receiving the JMX exporter, the socket initiator, the connector's object name, and the session exporter. These components are passed to the superclass to establish common connector management functionality, while the initiator reference is stored for accessing initiator-specific information.
The primary responsibility of this class is implemented in the getInitiatorAddresses() method. It retrieves all active initiator sessions from the underlying connector and iterates through each IoSessionInitiator object. For every session, it gathers important connection details, including the session identifier, the local network address used by the initiator, all configured remote socket addresses, and the JMX object name representing the session. These details are stored inside instances of the inner SessionInitiatorAddressRow class and later converted into JMX TabularData. This structured representation allows external monitoring tools to display connection information in an organized table format.
The inner SessionInitiatorAddressRow class contains helper methods that convert raw socket addresses into human-readable IP address and port combinations. The getLocalInitiatorAddress() method returns the local address used by the initiator, while the getInitiatorAddresses() method combines multiple remote addresses into a comma-separated string. This formatting simplifies the presentation of connection information for administrators.
Another important feature is the getQueueSize() method, which reports the current size of the initiator's message queue. Monitoring this value helps administrators evaluate connector performance and detect situations where outgoing messages are accumulating faster than they are transmitted.
The class also includes exception handling during the creation of JMX tabular data. Any OpenDataException generated while building the management data is converted into an IOException through the JmxSupport utility class, ensuring consistent error handling across the management subsystem.
Overall, this class provides a dedicated management layer for outgoing FIX connections by exposing network addresses, session information, queue statistics, and structured monitoring data through the JMX framework.
# 4. ConnectorAdmin.java
# Description
The ConnectorAdmin class is an abstract base class that provides common JMX management functionality for all FIX connectors in the QuickFIX/J framework. Both SocketAcceptorAdmin and SocketInitiatorAdmin inherit from this class, allowing them to reuse connector management features while implementing their own connector-specific operations. The class also implements the ConnectorAdminMBean and MBeanRegistration interfaces, enabling it to participate in the JMX registration lifecycle.
During object creation, the constructor receives references to the connector, session settings, JMX exporter, connector object name, and session exporter. It determines whether the connector acts as an Acceptor or an Initiator using runtime type checking and stores the connector role for later use. It also initializes the resources required for exporting and managing session MBeans.
The class contains an inner helper class named ConnectorSession, which represents information about an individual FIX session. This class provides methods for retrieving the session identifier, associated JMX object name, connection status, and remote network address. It acts as a data model that is later converted into JMX tabular data.
The getSessions() method retrieves all sessions associated with the connector, looks up the corresponding Session objects, and converts them into structured TabularData. Similarly, the getLoggedOnSessions() method filters only the currently active sessions and returns their JMX object names, allowing administrators to quickly identify active connections.
Connector lifecycle management is handled through the start(), stop(), and overloaded stop(boolean force) methods. These methods start or terminate the connector while recording management operations using the logging framework. Configuration and runtime exceptions are converted into IOException objects through the JmxSupport utility, ensuring consistent exception handling across the management layer.
The class also integrates with the JMX registration lifecycle through the preRegister(), postRegister(), preDeregister(), and postDeregister() methods. After successful registration, it automatically registers all available FIX sessions as individual JMX MBeans. It also listens for session property changes so that newly created sessions are registered dynamically. When the connector is removed from JMX, all associated session MBeans are automatically unregistered to prevent stale management objects.
Overall, this class serves as the central management layer for FIX connectors by handling connector lifecycle operations, session registration, monitoring, logging, and JMX integration while providing reusable functionality for both acceptors and initiators.
# 5. Dictionary.java
# Description
The Dictionary class represents a flexible configuration container that stores application settings as key-value pairs. It is primarily used by the QuickFIX/J framework to manage session configuration parameters and provides convenient methods for storing, retrieving, updating, and validating configuration values of different data types.
Internally, the class maintains its data using a HashMap, allowing configuration values to be accessed efficiently through their corresponding keys. Multiple constructors are provided to create an empty dictionary, initialize one with a name, copy an existing dictionary, or create a dictionary from another map. This flexibility allows configuration information to be reused or duplicated whenever necessary.
The class includes several getter methods such as getString(), getLong(), getDouble(), getBool(), and getDay(). Each method retrieves the requested value while verifying that both the key exists and the stored data type matches the expected type. If a key is missing, the class throws a ConfigError, while incorrect data types result in a FieldConvertError. These validation checks help prevent invalid configuration values from being used by the FIX engine.
Corresponding setter methods such as setString(), setLong(), setDouble(), setBool(), and setDay() allow configuration values to be added or updated. The day-related methods use the DayConverter utility to convert between integer representations and day names, ensuring consistent storage of weekday information.
Additional utility methods further improve configuration management. The has() method checks whether a specific configuration key exists, while the merge() method combines another dictionary into the current one by copying all of its entries. The toMap() method exposes the internal configuration data as a standard Java Map, allowing other components to process configuration values using standard collection operations.
Overall, the Dictionary class provides a reliable and reusable mechanism for managing configuration settings. By supporting multiple data types, validation, exception handling, and configuration merging, it forms an important part of the QuickFIX/J configuration subsystem.
# 6. Field.java
# Description
The Field<T> class is a generic base class that represents an individual field within a FIX protocol message. Every FIX message consists of multiple fields, where each field contains a numeric tag and its corresponding value. This class provides the core functionality required to store, manipulate, format, and validate these fields before they become part of a complete FIX message.
The class maintains several important attributes, including the field tag, the generic value object, cached string data, encoded byte representation, and a flag indicating whether the formatted output has already been calculated. This caching mechanism avoids unnecessary recalculations, improving performance when the same field is accessed repeatedly.
The constructor initializes the field with its tag number and initial value. Public methods such as getTag(), getField(), getObject(), and setObject() allow controlled access to the field's contents. Whenever the value or tag changes, the cached representation is invalidated to ensure that future calculations always reflect the latest data.
A key responsibility of this class is formatting the field into the standard FIX representation (tag=value). The toString() method generates this format and internally calls the private calculate() method. This method builds the formatted string, converts it into bytes using the configured character set when necessary, and stores the result for future reuse. This design minimizes repeated string construction and improves encoding efficiency.
The class also includes methods for calculating the encoded field length and checksum, both of which are essential when constructing valid FIX messages. These methods rely on the cached encoded representation to improve performance during message serialization.
Additional functionality includes implementations of equals() and hashCode(), allowing field objects to be compared based on their tag number and stored value. The protected objectAsString() method provides a customizable way for subclasses to define how different data types should be converted into string form before encoding.
Overall, the Field<T> class acts as the foundation of the QuickFIX/J message model. It combines data storage, FIX message formatting, encoding, checksum calculation, caching, and object comparison into a reusable component that supports all specialized FIX field implementations.
# 7. TabularDataAdapter.java
# Description
The TabularDataAdapter class is a utility component that converts different Java data structures into JMX TabularData, which is the standard format used by Java Management Extensions (JMX) for displaying structured management information. Instead of manually creating complex JMX objects, this class automates the conversion process and provides reusable methods for generating management tables from arrays, maps, JavaBeans, and lists of JavaBean objects.
The class contains several conversion methods, each designed to handle a specific type of input. The fromArray() method converts an array of objects into a simple JMX table by creating a row for every object and storing its string representation. The fromMap() method processes key-value pairs stored in a Java Map and creates a two-column table where each row represents one configuration entry.
For JavaBean objects, the fromBean() method uses Java Reflection through the Introspector and BeanInfo classes to examine all readable properties of a bean automatically. Instead of manually specifying every field, it dynamically discovers property names and values, ignores the default class property, and stores the remaining information inside JMX CompositeData objects. This makes the class flexible enough to work with different bean implementations without code modification.
The most advanced functionality is implemented in the fromBeanList() method. This method accepts a collection of JavaBeans, automatically analyzes their properties, generates appropriate table headers, builds a corresponding CompositeType, and finally creates a TabularData object containing every bean as a separate row. The helper methods createTableHeaders() and formatHeader() ensure that column names are generated in a consistent and readable format.
Throughout the conversion process, the class performs exception handling by catching reflection-related errors and wrapping them inside OpenDataException, which is the standard exception type used by the JMX Open MBean API. This provides consistent error reporting while hiding low-level implementation details.
Overall, the TabularDataAdapter class acts as a bridge between ordinary Java objects and JMX management data. By automatically converting application data into structured tables, it simplifies monitoring, debugging, and runtime administration within the QuickFIX/J framework.
# 8. BytesField.java
# Description
The BytesField class is a specialized implementation of the generic Field<T> class that is designed specifically for handling binary data in FIX messages. While the standard Field class can store values of any type, this class focuses on byte arrays (byte[]), allowing binary information to be stored and transmitted without requiring manual conversion by the developer.
The class provides two constructors. The first constructor creates an empty binary field with a specified tag number, while the second constructor initializes the field using both the tag number and an existing byte array. This allows binary data to be assigned during object creation or updated later.
To simplify interaction with binary values, the class includes the setValue() and getValue() methods. The setValue() method replaces the current binary content with a new byte array by calling the inherited setObject() method from the parent class. Similarly, the getValue() method retrieves the stored byte array directly, providing a clear and convenient interface for accessing binary field data.
The class overrides the protected objectAsString() method inherited from the Field class. Instead of relying on the default object conversion, it explicitly converts the stored byte array into a string using the character encoding defined by CharsetSupport. This ensures that binary data is encoded consistently before being inserted into a FIX message and maintains compatibility with the framework's configured character set.
Although the implementation is relatively small, the class plays an important role within the FIX engine by providing dedicated support for binary message fields. By extending the generic field infrastructure while specializing only the binary conversion logic, it avoids code duplication and maintains compatibility with the overall message processing framework.
Overall, the BytesField class provides a clean and efficient mechanism for storing, retrieving, encoding, and managing binary FIX message fields while taking advantage of the reusable functionality already implemented in the generic Field class.
# 9. CompositeDataFactory.java
# Description
The CompositeDataFactory class is a helper utility responsible for constructing JMX CompositeData objects, which are used to represent structured management information consisting of multiple named values. Instead of creating complex CompositeDataSupport objects manually, this class provides a simple and reusable interface for gradually collecting data items before generating the final composite object.
The class stores a reference to a predefined CompositeType, which specifies the structure of the composite data. It also maintains two internal lists that hold item names and their corresponding values. These collections grow dynamically as new values are added through the various setValue() methods.
To support different types of management data, the class overloads the setValue() method for objects, numeric values, and boolean values. Each call records the provided item name together with its associated value, allowing multiple properties to be accumulated before the final object is created. This design makes the class flexible enough to build composite data representing different types of runtime information.
Once all required values have been collected, the createCompositeData() method constructs a CompositeDataSupport object using the stored item names, values, and predefined composite type. This object can then be returned to JMX clients or included inside larger management structures such as TabularData.
The clear() method removes all previously stored item names and values, allowing the same factory instance to be reused for creating multiple composite objects without allocating new collections each time. This improves efficiency when large numbers of management objects are generated repeatedly.
Overall, the CompositeDataFactory class simplifies the construction of structured JMX management data by separating data collection from object creation. It improves code readability, reduces duplication, and provides a reusable solution for building composite management objects throughout the QuickFIX/J framework.
# 10. CompositeTypeFactory.java
# Description
The CompositeTypeFactory class is responsible for creating JMX CompositeType definitions that describe the structure of composite management data. A CompositeType specifies the names, descriptions, and data types of all attributes contained within a CompositeData object. This class simplifies the creation of these type definitions by providing an easy-to-use interface instead of requiring developers to construct them manually.
The constructor initializes the factory by storing the name and description of the composite type that will be created. Internally, the class maintains separate collections for attribute names, descriptions, and data types. These collections gradually grow as new items are added through the defineItem() methods.
The class provides two overloaded versions of the defineItem() method. One method allows the attribute name and description to be identical, while the second version accepts separate names and descriptions, providing greater flexibility when documenting management data. Each method also requires an OpenType, which specifies the data type of the corresponding attribute, ensuring that the generated composite type follows JMX validation rules.
After all required attributes have been defined, the createCompositeType() method combines the stored information and creates a fully configured CompositeType object. This object is later used by classes such as CompositeDataFactory and TabularDataAdapter to validate and organize structured management information before it is exposed through JMX.
By separating type definition from data creation, this class promotes modular design and improves code reusability throughout the management subsystem. Any component that needs to generate structured JMX data can define its data model once and reuse it whenever new management objects are created.
Overall, the CompositeTypeFactory class serves as the foundation for defining structured JMX data models. It provides a reusable and organized mechanism for describing management data, helping other components generate consistent and well-defined JMX objects across the QuickFIX/J framework.
